# Тестовое задание: сервис управления задачами (без хардкода)

## Контекст

Мы разрабатываем бэкенд на Java + Spring Boot.  
В рамках этого задания нужно реализовать небольшой сервис управления задачами, но **без хардкода** — данные должны храниться в базе данных через Spring Data JPA.

---

## Функциональные требования

### 1. Пользователь (User)
- `id` (Long, автоинкремент)
- `name` (String, не null)
- `email` (String, уникальный, не null)

### 2. Задача (Task)
- `id` (Long, автоинкремент)
- `title` (String, не null)
- `description` (String, опционально)
- `completed` (boolean, по умолчанию false)
- `deadline` (LocalDateTime, опционально)
- связь с пользователем (много задач у одного пользователя)

---

## Технические требования

### Сущности (Entity)
- Использовать JPA-аннотации (`@Entity`, `@Id`, `@GeneratedValue`, `@ManyToOne`, `@Column` и т.д.)
- Использовать Lombok для сокращения кода

### Репозитории (Repository)
Интерфейсы, наследуемые от `JpaRepository`, с методами:
- найти пользователя по email
- найти все задачи пользователя (с пагинацией `Pageable`)
- найти задачу по ID и ID пользователя (убедиться, что задача принадлежит пользователю)
- найти невыполненные задачи с дедлайном раньше текущего времени (с пагинацией)
- удалить задачу по ID и ID пользователя (вернуть количество удалённых записей)

### Сервисы (Service)
- `@Service` с бизнес-логикой
- создание пользователя
  поиск пользователя по ID (Возвращает UserDto и обрабатывает ситуацию, когда пользователь не найден)
- создание задачи (проверить, что пользователь существует)
- отметка задачи выполненной
- удаление задачи (только если она принадлежит указанному пользователю)
- получение всех задач пользователя с пагинацией и опциональной фильтрацией по статусу
- транзакции (`@Transactional`)
- возвращать `Optional` вместо `null`

### Контроллеры (Controller)
- Добавить REST-контроллеры, чтобы можно было проверить работу через Postman/Bruno.

---

## Запрещено
- Хранить данные в памяти (в списках, мапах, статических переменных)
- Возвращать `null` из поисковых методов (использовать `Optional`)
- Игнорировать исключения (try-catch или кастомные Exception вместе с `@RestControllerAdvice`)
- Использовать полевую инъекцию (`@Autowired` над полем) — только конструктор (можно использовать `@RequiredArgsConstructor`)

---

## Формат сдачи
- Создание собственной ветки на основе `feature/repo-entity-task`
